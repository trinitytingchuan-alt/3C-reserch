# 证据链标准（E## / V##）

## 概述

本文档定义 3C 竞品分析中证据的编号体系、结构化格式、核验标准与引用规范。

## 证据编号体系

### E## — 事实证据
格式：`E{三位数字序号}`，从 E001 递增，全局唯一。

每条 E## 证据必须包含：
```json
{
  "id": "E001",
  "claim": "一句话事实陈述（可验证）",
  "source": "具体出处（URL / 文件路径 / 截图）",
  "source_type": "official|media|community|ecommerce|database|social",
  "tier": "T0|T1|T2|T3",
  "verification_level": "L1|L2|L3",
  "verification_method": "端内实测|官网规格书|RTINGS 实验室|B站视频实测|小红书笔记|抖音测评|京东评价|亚马逊评论|Reddit讨论|...",
  "data_window": "2026-08-01",
  "category": "所属品类",
  "tag": ["anc", "battery", "comfort"],
  "notes": "补充说明（可选）"
}
```

### V## — 核验记录
格式：`V{三位数字序号}`，与 E## 一一对应。

每条 V## 核验记录：
```json
{
  "id": "V001",
  "evidence_id": "E001",
  "L1": {"passed": false, "note": "未进行端内实测"},
  "L2": {"passed": false, "note": "非官方发布数据"},
  "L3": {"passed": true, "source": "RTINGS 2026-07 headphone test"},
  "final_level": "L3",
  "verified_at": "2026-08-11T10:00:00+08:00",
  "reviewer": "Agent"
}
```

## 三级核验标准

### L1 — 端内实测
- 真机/模拟器/固件实际运行验证
- 需保留：操作录像 / 屏幕截图 / 固件版本号
- 最高置信度，可直接作为产品决策依据

### L2 — 官方渠道
- 品牌官网产品页、规格书 PDF、官方社区公告
- 固件更新日志（FOTA changelog）
- 官方认证参数（CCC/SRRC 等）
- 中高置信度，可作对比依据

### L3 — 第三方验证
- 专业媒体实测（RTINGS、DXOMARK、SoundGuys 等）
- KOL 视频/图文测评（B站、小红书、抖音）
- 电商平台参数页（京东/天猫/亚马逊）
- 用户社区高赞评论（需标注样本量）
- 中低置信度，需交叉验证

## 证据引用规范

### 在 PRD / HTML 报告中引用
- 行内引用：`(E001)` `(V001)` 
- 批量引用：`(E001, E005, E008)`
- 证据附录：报告末尾自动生成「证据链附录」区块

### 引用禁止事项
- ❌ 改写已有证据的 claim 描述
- ❌ 无编号的游离断言（"某评测说..."）
- ❌ 混用不同品类的证据
- ❌ 把 T3 来源当 T0 使用
- ❌ 把用户功能与平台机制对标（违反 feature_compare_logic）

### 证据更新规则
- 新数据只能新增 E##，不覆盖已有 E## 的 claim
- 已有证据失效时标注 `status: "deprecated"` + 替代证据编号
- 同一事实的补充信息用 `supplement` 字段追加

## 证据质量分级

| 等级 | 条件 | 置信度 | 可作对比依据 |
|------|------|--------|--------------|
| A 级 | L1 实测 + L3 多源交叉验证 | 高 | ✅ |
| B 级 | L2 官方 + L3 至少一个信源 | 中高 | ✅ |
| C 级 | 仅 L3 单一信源 | 中 | ✅（标注） |
| D 级 | L3 用户社区（无专业验证） | 低 | ⚠️（仅作参考） |

## 数据窗口

每条证据必须标注 `data_window`，表示该信息的时效窗口：
- 格式：`YYYY-MM-DD`（单日）或 `YYYY-MM-DD ~ YYYY-MM-DD`（区间）
- 超过 6 个月的证据自动标记 `stale: true`
- 报告页头标注整体数据窗口
