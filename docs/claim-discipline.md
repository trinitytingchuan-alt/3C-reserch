# 断言纪律与对比逻辑

## 概述

本文档定义 3C 竞品分析中的三条硬规则及其执行细则，确保所有分析产出经得起推敲。

---

## 规则一：verify_first — 现状三级核验

### 核心原则
任何关于竞品功能、性能、体验的断言，必须经过至少一级核验后才能写入报告。

### 三级核验体系
| 级别 | 核验方式 | 置信度 | 示例 |
|------|----------|--------|------|
| L1 | 端内实测 | 最高 | 亲手测试 Sony XM5 ANC 模式切换 |
| L2 | 官方渠道 | 高 | Apple 官网标注 AirPods Pro 降噪深度 |
| L3 | 第三方验证 | 中 | RTINGS 测量 Bose QC Ultra ANC 曲线 |

### 核验失败时的表述规范
❌ 禁止表述：
- "XX 产品没有降噪功能"
- "XX 品牌未提供固件更新"
- "XX 产品续航很差"

✅ 正确表述：
- "在 Tier 0-2 数据源中未发现 XX 产品的 ANC 功能描述（核验方式：官网规格书+电商参数页，数据窗口：2026-05~2026-08）"
- "未在官方固件日志中找到相关信息（L2 核验，2026-01~2026-08）"
- "京东差评中续航相关投诉占比 12%（L3，样本量 N=500+，2026-06~2026-08）"

### 核验覆盖要求
- 每篇报告的核心对比维度至少 80% 有至少一级核验
- P0 级优化建议必须至少 L2 核验
- 数字化断言（如"ANC 深度 34dB"）必须有可追溯的实测来源

---

## 规则二：claim_discipline — 断言纪律

### 两条红线

#### 红线 1：不伪称"竞品无某功能"
- 原因：信息不对称，可能竞品已具备但未在已查源中发现
- 替代方案：标注核验方式 + 数据窗口 + "未发现"而非"没有"
- 例外：如果 Tier 0 官方明确声明不支持（如"本产品不支持无线充电"），可直接表述

#### 红线 2：不立不可观测行为的伪需求
禁止推测以下类型的"优化建议"：
- 内部算法逻辑（如"优化降噪算法"——只能提"提升降噪深度至 XX dB"）
- 商业策略（如"调整定价策略"——只能提"竞品定价区间 X-Y，建议参考"）
- 未公开的技术路线（如"换用 XX 芯片"——只能提"竞品使用 XX 方案达到 YY 效果"）

可观测 VS 不可观测判定表：
| 可观测（可分析） | 不可观测（禁止推测） |
|------------------|----------------------|
| ANC 深度 (dB) | 降噪算法内部参数 |
| 续航时长 (小时) | 功耗优化策略 |
| 蓝牙版本/编码 | 连接调度算法 |
| App 功能列表 | 后台推送策略 |
| 外观材质 | 供应链选择 |
| 用户评价情感分布 | 品牌口碑成因 |

## 规则三：feature_compare_logic — 同类可比

### 核心原则
功能对比必须同类可比——用户功能 vs 用户功能，平台机制 vs 平台机制。

### 功能分类体系
| 维度类别 | 示例 | 可对比对象 |
|----------|------|------------|
| **用户功能** | ANC 模式切换、EQ 调节、触控操作、语音助手唤醒 | 仅与其他产品的用户功能对比 |
| **性能指标** | 续航、延迟、连接距离、充电速度 | 仅与其他产品的性能指标对比 |
| **平台能力** | App 功能覆盖、固件更新频率、生态联动 | 仅与其他产品的平台能力对比 |
| **供给策略** | 保修政策、价格策略、配色方案 | 仅与其他产品的供给策略对比 |

### 跨维度混比判定（典型违规案例）

❌ **违规 1**：把用户侧功能与技术方案对标
> "我们的 ANC 使用前馈式方案，竞品使用混合式方案，说明我们需要升级到混合式"
> → 应改为"竞品 ANC 深度 34dB vs 我方 28dB（E001, E005），建议提升至 33dB+"

❌ **违规 2**：把用户功能与平台供给机制对标  
> "竞品有 AI 内容推荐，我们没有"
> → 检查 AI 推荐是否为可观测用户功能（如推荐按钮），若是则归为用户功能对比

❌ **违规 3**：把固件能力与硬件规格对标
> "竞品通过固件更新支持了 LE Audio，说明我们需要更新固件"
> → 先确认我方硬件是否支持 LE Audio（蓝牙芯片型号/规格书），不能脱离硬件谈固件

### 对比正确姿势
```
我方 [用户功能A] 的表现是 [指标X]
竞品 [用户功能A] 的表现是 [指标Y]
差距 = |X - Y|
优化目标 = [指标Z]，依据：竞品已实现 (E##)
```

### 禁止使用的对比句式
- "竞品的 XX 机制比我们的先进" → 需具体到"XX 功能的哪个可测指标"
- "我们需要对标竞品的 XX 策略" → 策略不可观测，需转为功能/性能对标
- "从 XX 的运营方式来看" → 运营方式不可知，只能说可观测结果

## QA 自动化检查项

Harness `qa.mjs` 会自动检查以下违规：

| 检查项 | 检测方式 | 严重度 |
|--------|----------|--------|
| 无出处断言 | 正则匹配"没有/无此功能/不具备"等模式 | ERROR |
| 不可观测行为 | 关键词：算法优化/调整策略/内部机制 | WARNING |
| 跨维度混比 | 关键词共现检测（用户功能词 + 平台机制词） | ERROR |
| 缺失核验标注 | 检测"未发现X"但无 L1/L2/L3 标注 | ERROR |
| 数字化断言无出处 | 正则匹配数字 + 单位但无 E## 引用 | ERROR |
