# 断言纪律

> 硬性约束：所有关于 "该公司缺少/没有/不具备某能力" 的断言，必须经过三级核验并标注核验级别 + 数据窗口。

---

## 一、三大断言红线

### 红线 1：禁止无核验断言"无此功能"
"红果无 AI 内容标识" → 错误（未经核验）
"经端内实测(L1)和官方文档确认(L1)，红果端内具备基础 AI 标识但不对用户披露，无分级体系" → 正确

差距描述公式：
```
[已有基础水平] + [具体差距内容] + [核验方式 (L1/L2/L3)] + [数据窗口]
```

### 红线 2：禁止立不可观测的伪需求
凡声称"用户需要 X"且无法被公开可观测行为（评论/搜索/购买/投诉）验证的，一律视作伪需求。
- "用户需要更个性化推荐" 且无法在社区找到相关讨论 → 伪需求
- "用户需要更快的充电速度"且有大量充电速度抱怨评论 → 真需求

### 红线 3：禁止跨维度混比
用户功能与用户功能对比，平台机制与平台机制对比。
- "A 有会员体系，B 没有" → 用户功能 vs 用户功能 ✓
- "A 平台有创作者补贴机制，B 没有用户信息披露功能" → 跨维度混比 ✗

---

## 二、gap 描述模板

所有差距描述必须遵循以下格式：

```
[公司在某维度的当前水平] → 经 [核验方式 (L1/L2/L3)] 确认
[具体差距内容] → 与 [对标对象] 的差距
[升级建议] → 从 [当前水平] 升级到 [目标水平]
[数据窗口] → 2025-08 ~ 2026-08
```

---

## 三、场景优先断言规则

### 场景采集断言
"用户在 [场景] 中遇到 [痛点]" 
→ 必须提供 ≥2 条来自不同平台的用户声音证据 (L3)
→ 同一场景中 ≥3 个独立用户表达了类似痛点

### IDEa 有效性断言
"建议开发 [产品/功能] 解决 [痛点]" 
→ 必须说明发现路径 (scene-pain/competitor-gap/cross-industry)
→ 如果是 competitor-gap，必须标注竞品 + 验证信号

### 需求真实性断言
"[需求] 是市场高呼声"
→ 必须提供趋势证据（≥1条，搜索/销量/社媒 YoY 增长）
→ 必须至少 ≥2 个不同数据源 Tier
→ 说明"为什么不是伪需求"（反证法：如果不存在需求，市场观测信号应为何？）
