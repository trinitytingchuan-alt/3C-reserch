# 数据质量评判准则（Data Quality Criteria）

> 版本：1.0.0
> 原则：**每条功能需求必须由 ≥10 条强相关数据源支撑，且数据之间形成完整推导逻辑链**。
> 适用范围：所有进入 TOP5 / 功能需求清单的 IDEA。

---

## 一、相关性三级分类

每条证据（E##）在关联到具体功能需求时，须标注其与当前功能的**相关性级别**：

| 级别 | 名称 | 定义 | 示例 |
|------|------|------|------|
| **S** | 直接支撑 | 数据直接指向当前功能的核心场景、痛点或方案 | 「用户在出差场景下抱怨充电宝+线缆太多」（直接证明 ID-002 DeskHub 场景痛点） |
| **A** | 间接强关联 | 数据支撑功能的前置条件或关联逻辑 | 「数字游民 6 年增长 130%」（证明 ID-002 目标用户规模在扩大） |
| **B** | 环境/背景 | 数据仅提供宏观背景参考，不直接证明功能存在 | 「安克营收 305 亿」（提供公司背景，不直接证明某功能需要存在） |

### S 级判定标准（满足任一即可）

1. **场景直证**：数据描述了目标用户在该功能对应场景下的真实行为或体验
2. **痛点直证**：数据直接表达了用户对当前功能拟解决的问题的不满或需求
3. **方案直证**：数据描述了市场上已有的类似方案或竞品在该方向的行动
4. **技术直证**：数据直接证明/证伪当前功能的技术可行性

### A 级判定标准（满足任一即可）

1. **规模间接证**：数据证明目标用户群体/市场规模在增长或足够大
2. **趋势间接证**：数据证明相关搜索/讨论/消费行为在递增
3. **竞品间接证**：数据描述了竞品在相关领域（但非直接对标功能）的动向

### B 级（默认降级）

不符合 S/A 级标准的证据，仅作为背景补充。典型 B 级数据：
- 公司整体财报/营收数据
- 行业总量统计（不指向具体场景）
- 通用技术白皮书（不指向具体功能）

---

## 二、准入门槛（QA 强制校验）

每条 TOP5 功能需求的 validationChain 须同时满足：

| 指标 | 最小值 | 说明 |
|------|--------|------|
| 总数据源（去重后 E## 数） | ≥ 10 | 跨 validationChain 所有维度去重 |
| S 级证据 | ≥ 4 | 直接证明场景/痛点/方案存在 |
| A 级证据 | ≥ 3 | 证明市场/趋势/竞品响应 |
| B 级证据 | ≤ 3 | 仅做背景补充，不得超过此上限 |
| 来源类型 | ≥ 4 | 官方/行业报告/用户声音/搜索趋势/竞品产品页等 |

### 功能需求清单（>75 分）准入门槛

| 指标 | 最小值 |
|------|--------|
| 总数据源 | ≥ 6 |
| S 级证据 | ≥ 2 |
| A 级证据 | ≥ 2 |

## 三、弱相关拦截规则（以下数据不计入有效数据源）

1. **泛化市场数据**：仅证明「市场很大」但不指向具体场景/痛点的数据
   - 例：「全球充电宝市场 186 亿美元」若不关联到具体功能场景，仅为背景
2. **公司名关联**：与当前功能仅共享公司名/品类名但无因果联系的数据
   - 例：安克年报数据对「爬楼扫地机器人」(ID-007) 不构成 S 级支撑
3. **通用证据过度复用**：被 > 3 个 IDEA 引用的证据自动降级为 B 级
   - 例：E001（安克年报）、E004（市场总量）被几乎所有 IDEA 引用 → 仅算 B 级
4. **六度分隔关联**：需要 ≥ 3 步推导才能关联到当前功能的数据
   - 例：「全球 GDP 增长」→「消费增长」→「充电需求增长」→「某功能需要」——链条过长

## 四、来源类型定义（≥ 4 种要求）

| 来源类型 | 典型数据源 | 对应 Tier |
|---------|-----------|-----------|
| 官方数据 | 公司财报/公告/产品页/国标文件 | Tier 0 |
| 行业报告 | Gartner/Canalys/IDC/Mordor/Grand View Research | Tier 1 |
| 专业评测 | The Wirecutter/Tom's Guide/iFixit 拆解 | Tier 1-2 |
| 用户声音 | Amazon/京东评论、Reddit/知乎/小红书讨论 | Tier 2 |
| 搜索趋势 | Google Trends/百度指数/阿里巴巴商业洞察 | Tier 2-3 |
| 竞品产品 | 竞品官网产品页/发布会/招聘信息 | Tier 0-1 |
| 社区/社媒 | Reddit/微博/TikTok/YouTube 评论 | Tier 2 |

## 五、在 ideas.json 中的标注方式

在 validationChain 的每个维度中新增 `relevance` 字段：

```json
"marketVoice": {
  "evidenceIds": ["E013", "E0xx"],
  "relevance": ["A", "S"],
  "logic": "..."
}
```

同时在顶层新增 `dataSourceSummary` 汇总字段：

```json
"dataSourceSummary": {
  "total": 12,
  "sTier": 5,
  "aTier": 4,
  "bTier": 3,
  "sourceTypes": ["官方数据", "行业报告", "用户声音", "搜索趋势", "竞品产品"]
}
```

## 六、QA 校验规则

qa.mjs 将新增以下检测项：

1. **总量检测**：validationChain 中去重 evidenceIds ≥ 10（TOP5）/ ≥ 6（功能清单）
2. **S 级检测**：标注为 S 级的证据 ≥ 4（TOP5）/ ≥ 2（功能清单）
3. **B 级上限**：B 级证据 ≤ 3
4. **来源类型检测**：sourceTypes ≥ 4 种
5. **通用证据降级检测**：被 > 3 个 IDEA 引用的证据不计入 S 级
6. **logic 字段相关性**：logic 中须提及当前功能的 ID 或标题关键词（防止泛化描述）

---

## 七、与现有规范的关系

- 本准则是 `evidence-standard.md` 的**补充**，不替代原有的 Tier 分级和三级核验体系
- 原有 validationChain 五源强支撑（market-validation-loop.md）仍为**前置硬门槛**
- 本准则在五源基础上增加**数据质量深度要求**（不只是「有没有」，还要「强不强」）
