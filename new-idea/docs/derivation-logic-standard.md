# 数据推导链路闭环标准（Derivation Logic Standard）

> 版本：1.0.0
> 原则：**功能需求的验证数据不是散点集合，而是环环相扣的因果链**。
> 适用范围：所有进入 TOP5 / 功能需求清单的 IDEA 的 validationChain。

---

## 一、推导链路模型

每个功能需求的验证数据须形成如下完整因果链：

```
┌─────────┐    在该场景下存在    ┌─────────┐
│ 用户场景 │ ──────────────────→ │ 用户痛点 │
└────┬────┘                     └────┬────┘
     ↑                               ↓
     │                        针对痛点市场出现
     │                               ↓
┌─────────┐                    ┌─────────┐
│ 竞品趋势 │ ←───────────────── │ 市场响应 │
└────┬────┘    竞品已做/在做    └─────────┘
     ↓
     │ 基于竞品缺口/跨行业参考
     ↓
┌─────────┐
│ 我方方案 │
└─────────┘
```

**核心要求**：数据之间不是孤立散点，而是形成「场景→痛点→市场响应→竞品行动→我方方案」的闭环。

---

## 二、五环相扣规则

### 规则 1：场景-痛点对应（Scene-Pain Correspondence）

**用户声音数据必须同时描述场景和痛点**，孤立的痛点吐槽不构成场景痛点。

- 合格：「出差住酒店时，桌面被充电器和线缆占满，找不到足够插座」（场景+痛点同时出现）
- 不合格：「充电宝太重了」（孤立吐槽，未关联到具体使用场景）
- 不合格：「数字游民增长 153%」（仅有场景规模，无痛点描述）

**QA 检测方式**：userVoice 维度的 logic 字段须同时包含场景关键词和痛点关键词。

### 规则 2：痛点-竞品响应（Pain-Competitor Response）

**竞品验证数据须说明竞品如何回应这个痛点**（已做/在做/做不了），而非仅列出竞品功能列表。

- 合格：「倍思率先拿到新国标 3C 认证，但仅停留在单品合规，无品牌做跨设备电池健康管理生态」（说明竞品做了什么、没做什么）
- 不合格：「倍思有充电宝产品」（仅列出竞品存在，未说明与本功能痛点的关系）

**QA 检测方式**：competitorValidation 维度的 logic 字段须包含竞品的具体行动描述和缺口描述。

### 规则 3：竞品-市场空间（Competitor-Market Space）

**市场声音数据须证明该场景/痛点的市场容量足够且在增长**，而非仅说「XX 市场百亿」。

- 合格：「便携太阳能折叠板市场 2025 年 7.37 亿美元、CAGR 5.5%，轻量太阳能方案有可量化细分市场」（指向具体细分）
- 不合格：「全球充电宝市场 186 亿美元」（泛化市场数据，未指向具体功能场景）

**QA 检测方式**：marketVoice 维度的 logic 字段须包含与当前功能直接相关的市场细分数据。

### 规则 4：方案-缺口对接（Solution-Gap Alignment）

**解决方案必须明确说明填补了哪个竞品缺口**，不能凭空设计。

- 合格：「竞品 UPS 全聚焦 IT 市场（笨重/噪音/贵），本方案迁移为消费级静音/家居化形态」（明确缺口+方案对应）
- 不合格：「设计一个智能充电基站」（凭空设计，未说明为什么是这个形态）

**QA 检测方式**：idea 的 solution 字段须引用至少一个竞品缺口或跨行业参考。

### 规则 5：跨行业-可迁移性（Cross-Industry Transferability）

**跨行业参考须说明源行业方案和目标行业场景的具体映射关系**。

- 合格：「借鉴苹果手机电池健康（仅容量百分比）的功能空白，手机端已验证用户认知，充电品类仍无同类管理能力」（明确源→目标映射）
- 不合格：「其他行业也有类似方案」（模糊引用，未说明映射关系）

**QA 检测方式**：crossIndustryRef 维度的 logic 字段须包含源行业和目标行业的具体对应描述。

## 三、chainLink 字段规范

在 validationChain 的每个维度中新增 `chainLink` 字段，显式描述该维度如何与其他维度形成逻辑闭环：

```json
"marketVoice": {
  "evidenceIds": ["E013", "E0xx"],
  "logic": "安克披露端侧AI+家庭机器人战略反映消费电子向智能化管理转型",
  "chainLink": "市场智能化趋势(E013) → 支撑电池健康管理场景(ID-001)的技术方向 → 竞品仅单品合规(E010)留下生态级机会窗口"
}
```

### chainLink 书写规范

1. **必须跨维度引用**：至少引用另一个维度的证据或结论
2. **必须用因果连接词**：→ / 因此 / 导致 / 支撑 / 证明 / 留下
3. **必须提及当前功能**：显式引用功能 ID 或标题关键词
4. **禁止泛化推导**：不得使用「大趋势利好」「市场整体向好」等无具体因果的表述

---

## 四、推导链路完整性评估

qa.mjs 将新增推导链路一致性检查：

| 检查项 | 描述 | 不通过后果 |
|--------|------|-----------|
| chainLink 存在性 | 每个维度是否有 chainLink 字段 | WARN（首版）→ ERROR（后续） |
| 跨维度引用 | chainLink 是否引用了 ≥1 个其他维度的证据 | WARN |
| 场景-痛点对应 | userVoice.logic 是否同时含场景词和痛点词 | ERROR |
| 竞品响应描述 | competitorValidation.logic 是否含竞品行动+缺口 | ERROR |
| 方案缺口对接 | solution 字段是否引用竞品缺口 | ERROR |

---

## 五、反模式（Anti-Patterns）——以下情况判定为推导链路断裂

1. **散点堆砌**：evidenceIds ≥ 10 条但彼此无逻辑关联，各维度 logic 各自独立
2. **因果跳跃**：从市场规模直接跳到功能需求，中间缺少场景/痛点/竞品响应环节
3. **循环论证**：用「市场大→所以需要」和「有需要→所以市场大」互相论证
4. **伪跨行业**：crossIndustryRef 引用的行业与目标场景无实质映射关系
5. **万能证据**：同一条证据被用在 > 5 个不同功能的 S 级中（说明该证据过于泛化）

## 六、与现有规范的关系

- 本规范是 `market-validation-loop.md`（五源强支撑）的**深化**
- 五源解决「有没有」，本规范解决「逻辑通不通」
- 与 `data-quality-criteria.md`（数据质量准则）配合使用：
  - data-quality-criteria 管「每条数据的质量」
  - 本规范管「数据之间的逻辑关系」
