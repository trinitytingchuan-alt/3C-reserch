# 产品机会挖掘方法论

> 参考来源：安克（Anker）创新四步法（半佛仙人·安克创新体系分析）  
> 适用：输入任意公司 → 挖掘该公司产品机会与空白市场

---

## 一、安克创新四步法

### Step 1：大量假设
不受限于现有产品线，基于"看趋势、看场景、看人群、看痛点"四个视角提出海量假设。
- 看到趋势 → 关注技术/消费/社会趋势
- 看到场景 → 关注目标用户真实生活/工作中的环境
- 看到人群 → 关注人群特征、规模、行为变化
- 看到痛点 → 关注场景中未被解决的困难

### Step 2：大量观察
通过线上线下多渠道收集证据，验证假设的可靠性。
- 线上：电商评论/社区讨论/社媒趋势/搜索数据
- 线下：实地观察/用户访谈/场景还原

### Step 3：AI + 专家排除错误答案
用数据+逻辑+专家经验剔除不可行的假设。
- 技术可行性评估
- 市场规模校验
- 竞品格局分析

### Step 4：大心脏快速试错
用最小成本验证最可能的方案；十次试错一次成功就值。
- 原型验证
- 种子用户测试
- 快速迭代

## 二、场景优先三路径（核心创新）

### 路径A：场景-痛点（Scene → Pain → Solution）
**核心原则：从客群真实生活场景出发，而非从产品出发。**

收集目标客群的真实生活/工作场景（非产品使用场景）。在场景中识别：他们遇到什么困难？什么让他们不爽？什么浪费了他们的时间/金钱/精力？

然后针对"场景-痛点"对设计方案，摆脱现有产品的思维束缚。

**为何必须场景优先？**
- 防止"先验偏差"：如果先看产品再找场景，你只会找到产品已经解决的场景
- 防止"锤子找钉子"：拿了产品当锤子，看什么都像钉子
- 能发现"真正的空白"：有些场景中用户默默忍受着痛点，从未想过产品能解决

### 路径B：竞品-缺口（Competitor Gap）
找到竞品已被市场验证的品类/功能，评估目标公司是否跟进、跟进价值。

**操作流程**：
1. 识别同行业 3-5 个主要竞品
2. 列出竞品近 18 个月新推出的品类/功能
3. 筛选其中具有市场验证信号（销量增长/用户好评/媒体关注）的项目
4. 对目标公司现状做功能/品类对照
5. 筛选出目标公司尚未跟进的缺口
6. 评估缺口价值（市场规模/技术可行性/战略匹配）

### 路径C：跨行业-迁移（Cross-Industry Transfer）
从其他行业已验证的解决方案模式中寻找灵感，迁移到本行业对应场景。

**操作方法**：
1. 识别本行业用户的某种痛点模式
2. 寻找其他行业解决类似痛点的方案
3. 评估方案可迁移性（技术/场景/人群适配）
4. 设计跨行业迁移方案

## 三、五维采集

### 1. 场景采集（客群真实生活/工作场景）
- 目标客群细分
- 各细分客群的典型一日场景（时间/地点/活动/设备/情绪）
- 场景中存在的痛点和未被满足的需求:：
  - 一线城市上班族；下班后充电场景
  - 户外露营爱好者；睡前娱乐场景
  - 数码发烧友；随身设备充电管理场景

### 2. 客群画像
- 人口统计（年龄/性别/收入/地域）
- 消费行为（购买频次/渠道/客单价/品牌偏好）
- 数字生活（社交媒体平台/内容消费习惯）
- 价值观与生活方式

### 3. 产品参数
- 公司现有产品线列表（含规格/价格/上市时间/市场份额/用户评分）
- 产品技术栈和供应链
- 产品毛利结构和成本构成

### 4. 竞品格局
- 同行业主要竞争对手
- 竞品近期推出的新品类/功能（带验证信号）
- 竞争空白区域

### 5. 趋势扫描
- 搜索趋势（Google/Baidu 趋势）
- 社媒热度（话题量/情感分析 YoY 增长）
- 电商销量趋势
- 行业报告预测
- 技术成熟度曲线

## 四、交叉验证体系

### 三级核验
- **L1（一级核验）**：端内实测 / 官方公告 / 财报 / 白皮书
- **L2（二级核验）**：专业媒体评测 / 行业报告 / 第三方审计
- **L3（三级核验）**：社区讨论 / 电商评论 / 社媒声音

### 数据源分级
- **Tier 0**：官方公告/财报/白皮书（权威性最高）
- **Tier 1**：行业报告/第三方审计/专业评测
- **Tier 2**：社区/电商/社媒（用户声音）
- **Tier 3**：趋势工具/搜索引擎（宏观信号）

### 伪需求拦截机制
每条进入 TOP5 的需求必须满足：
1. ≥ 3 条证据（其中 ≥ 1 条趋势证据）
2. ≥ 2 个不同数据源 Tier
3. 场景-痛点-方案完整闭环
4. 三专家评审均已打分

### 根因多点验证（Root-Cause Multi-Source Validation）
**单一来源只能构成"假设"，不得直接定义为"根因"。** 凡推导链中标注「→ 直接定义根因」的结论，必须满足：
1. **≥ 2 个独立来源交叉验证**（不同发布方/不同媒体，非同一来源转发）
2. 来源可点击、可追溯（真实 URL + 日期）
3. 在 DERIVATION 中显式列出交叉验证证据（`cross` 字段）
4. 若仅有单条来源 → 降级为"假设/待验证"，不得写入根因表述

### 用户场景数据源（Scenario Source Requirement）
**用户场景必须来自真实用户声音收集，并附数据源引用：**
1. 每个场景（User Scenario）必须挂 ≥ 1 条真实来源（链接 + 日期）
2. 来源类型标注：`真实用户声音`（评论/社区/社媒）/ `媒体报道` / `官方来源`
3. 场景文本不得虚构；无来源的场景不得进入 PRD
4. 场景来源与证据链（E##）允许复用，但同一场景至少 1 条来源必须独立于该需求的竞品缺口证据

## 五、需求真实性判定标准

一个需求必须同时满足以下条件才被认定为"真实市场高呼声需求"：

1. **痛点可观测**：用户在公开渠道表达了该痛点（评论/社区/社媒）
2. **频率可统计**：痛点的出现频率可通过数据量化
3. **趋势可追踪**：相关搜索量/讨论量/购买量呈现增长趋势
4. **规模可估算**：受影响人群规模可通过第三方数据估算
5. **愿意付费**：存在用户为该痛点付费或使用替代方案的证据
6. **竞品已做**（可选增强项）：至少 1 个竞品已在该方向投入
