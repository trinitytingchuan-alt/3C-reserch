# 新功能 IDEA 市场验证闭环（Market Validation Closed Loop）

> 版本：2.0.0  
> 原则：**每个新功能 IDEA 必须有数据支撑的完整验证链路**。  
> 产出该功能的各数据源之间须有**明确强支撑逻辑**：较多市场声音、竞品验证、行业验证、参考行业验证、用户声音——所有源头数据都强支撑该功能，才能判定为真实需求。

---

## 一、为什么需要闭环（对比旧逻辑）

**旧逻辑（不足）**：一条 IDEA 挂 3 条证据即可通过 QA。但 3 条证据可能都来自同一维度（如全是行业报告），没有"用户真实痛点"或"竞品已证明"，导致伪需求漏网。

**新逻辑（闭环）**：一个功能要被认定"真实需求"，必须同时通过 **5 个验证维度**，且每个维度由**独立数据源**强支撑。缺任一维度，该 IDEA 不得进入 TOP5。

---

## 二、五源强支撑验证维度

每个功能 IDEA 在 `ideas.json` 中新增 `validationChain` 字段，显式列出五个维度的支撑证据：

```json
"validationChain": {
  "marketVoice": {        // ① 市场声音：市场够大且在增长
    "evidenceIds": ["E003", "E004"],
    "logic": "全球充电宝市场 140亿→283亿美元, CAGR 9.2%, 证明市场空间足够"
  },
  "competitorValidation": {  // ② 竞品验证：同类已被市场接受
    "evidenceIds": ["E010"],
    "logic": "倍思已率先推出新国标合规产品, 证明该品类已进入市场"
  },
  "industryValidation": {   // ③ 行业验证：处于上升通道
    "evidenceIds": ["E009"],
    "logic": "GB 47372-2026 强制国标 2027 实施, 安全合规成为行业趋势"
  },
  "crossIndustryRef": {     // ④ 参考行业验证：路径可复用
    "evidenceIds": [],
    "logic": "参考车联网/电池管理 BMS 行业, 健康管理生态已被验证 (如可复用路径)"
  },
  "userVoice": {            // ⑤ 用户声音：真实痛点非伪需求
    "evidenceIds": ["E005", "E006"],
    "logic": "Amazon/京东评论区高频吐槽'线缆管理/充电焦虑', 不同平台 ≥2 条"
  }
}
```

## 三、最小强支撑要求（QA 强制）

| 验证维度 | 最小证据数 | 数据源要求 | 缺失后果 |
|---------|-----------|-----------|---------|
| ① 市场声音 marketVoice | ≥1 | Tier1 行业报告/市场规模 | 需求降级至观察池 |
| ② 竞品验证 competitorValidation | ≥1 | Tier1/2 竞品已上功能 | 无法证明已被接受 |
| ③ 行业验证 industryValidation | ≥1 | Tier0/1/2 行业趋势 | 无法证明上升通道 |
| ④ 参考行业验证 crossIndustryRef | ≥1（或明确"无可参考行业"并说明理由） | 跨行业案例 | 无法证明路径可复用 |
| ⑤ 用户声音 userVoice | ≥2 且来自**不同平台** | Tier2/3 L3 真实评论 | 无法证明真实痛点 |

> 任一维度证据为 0 且无合理说明 → QA 报错（`ERROR`），该 IDEA 强制降级，不得进入 TOP5。

---

## 四、强支撑逻辑要求（每条证据须与功能有直接因果）

- **禁止六度分隔式牵强关联**：证据必须与"该功能为何存在"有直接因果。
- **证据编号必须真实存在**：QA 会校验 `validationChain` 里的每个 E## 已定义（防幽灵引用）。
- **数据源差异化**：用户声音须来自 `dataSourceStrategy.userVoiceChannels` 指定的地理市场渠道（海外客群 → Amazon/Reddit/Trustpilot）。

---

## 五、闭环在流水线中的位置

```
感知层采集 → 推理层推导出 IDEA → 【市场验证闭环】→ 三专家评审 → 评分 → TOP5
                                    ▲
                                    │ QA 强制校验 validationChain 五维齐全
                                    └ 任一维缺失 → 降级至功能清单/观察池
```

---

## 六、与 claims / scoring 的关系

- `validationChain` 是**进入评审前的硬门槛**（前置门），三专家评分是**通过后的价值排序**（后置排序）。
- 一个 IDEA 可能 5 维齐全但仍评分不高（如技术难、市场小），但它一定是"真实需求"。
- 一个 5 维不全的 IDEA，即使评分高也**不得**进入 TOP5（QA 拦截）。

---

## 七、报告透出约束

> 引用自 `AGENTS.md` 规则 8「报告透出红线」。

市场验证闭环的内部机制（五源强支撑、validationChain、QA 强制校验等）不得在报告正文中透出。报告中可用如下表述：
- 内部：「该 IDEA 五源强支撑齐全」
- 报告：「该需求经多维度市场验证，具备充分的数据支撑」
