# 证据规范

> 证据编号规则：E{编号}（全局唯一，不可删除/重用）
> 核验编号规则：V{编号}（关联核验级别 + 数据窗口）
> 数据窗口：2025-08 ~ 2026-08（默认，可案例级覆盖）

---

## 一、证据编号体系

### E## 证据编号
每条证据获得全局唯一编号 E001、E002、...，系统级递增，永不复用。

### V## 核验记录
每条核验记录记录：核验级别、核验来源、核验日期、数据窗口。

---

## 二、三级核验

| 级别 | 名称 | 定义 | 示例源 |
|------|------|------|--------|
| L1 | 官方渠道 | 官方公告 / 财报 / 白皮书 / 产品页面 | 安克官网、FCC认证、财报 |
| L2 | 专业媒体 | 行业报告 / 第三方审计 / 专业评测 | Canalys报告、The Wirecutter |
| L3 | 用户声音 | 社区讨论 / 电商评论 / 社媒 | Reddit、Amazon评论、微博 |

---

## 三、数据源分级

| Tier | 权威度 | 数据源类型 | 典型来源 |
|------|--------|-----------|---------|
| Tier 0 | 最高 | 官方数据 | 公司财报、FCC/CE认证、专利数据库 |
| Tier 1 | 高 | 行业权威 | Gartner/Canalys/IDC报告、Wirecutter |
| Tier 2 | 中 | 社区电商 | Amazon/京东评论、Reddit、知乎 |
| Tier 3 | 辅助 | 宏观信号 | Google Trends、百度指数、SimilarWeb |

---

## 四、趋势证据要求

每条 TOP5 需求必须包含 ≥1 条趋势证据，形式包括：
- 搜索量 YoY 增长率（Google Trends / 百度指数）
- 社媒讨论量 YoY 增长率
- 电商销售量 YoY 增长率
- 行业报告预测增长率
- 技术采纳曲线位置（处于早期多数/晚期多数/落后者等）

---

## 五、禁止行为

- 编造证据编号（幽灵引用 E-news、E-fake 等）
- 证据与需求无直接关联（六度分隔式的牵强关联）
- 单一来源过度依赖（≥2 个 Tier 必须来自不同数据源类型）
- 泛化引用（必须指明具体数据源 + 数据点）

---

## 六、报告透出约束

> 引用自 `AGENTS.md` 规则 8「报告透出红线」。

证据规范中的内部术语（Tier 分级、E##/V## 编号、三级核验级别等）在 HTML 报告中可展示为面向用户的友好形式：
- Tier 0 → 「官方数据」 / Tier 1 → 「行业报告」 / Tier 2 → 「用户声音」
- E## 编号可保留（作为可追溯标识），但不得暴露 evidence.json 文件名
- 核验级别可用「官方验证」「行业验证」「用户反馈」等面向受众的表述
